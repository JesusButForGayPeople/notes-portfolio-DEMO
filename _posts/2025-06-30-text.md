title: Text Rendering With Glyphon

Text rendering in games presents unique performance challenges. Poorly optimized text systems can significantly impact frame rates, as I discovered while building a Doom-like engine last summer. My attempt at a custom glyph rasterizer halved the framerate and produced jagged results.

This experience led me to seek a proven solution for Mirador. After evaluating options, I chose [glyphon](https://github.com/grovesNL/glyphon), a GPU-accelerated text rendering library that integrates well with wgpu. Glyphon provides high-quality text rendering with support for custom glyphs, making it suitable for Mirador's current and future needs.

## Integration Challenges

The integration wasn't straightforward. Mirador doesn't use wgpu directly but accesses it through egui_wgpu to support real-time developer interfaces. Glyphon traditionally expects wgpu as a standalone crate, and version mismatches between egui_wgpu's wgpu and glyphon's expected version prevent compilation.

This constraint required using glyphon version 0.8, which expects wgpu 24 - the same version provided by `egui_wgpu::wgpu`. This version alignment ensures compatibility while maintaining the developer interface functionality.

## API Design

Glyphon's API requires many parameters for accurate text placement and styling. Rather than passing these parameters directly throughout the codebase, I created a wrapper that provides a simpler interface. The wrapper organizes glyphon's requirements into nested structs that work together to specify text rendering.

The `TextStyle` struct controls visual appearance:

```rust
pub struct TextStyle {
    pub font_family: String,
    pub font_size: f32,
    pub line_height: f32,
    pub color: Color,
    pub weight: Weight,
    pub style: Style,
}
```

The `TextPosition` struct handles layout:

```rust
pub struct TextPosition {
    pub x: f32,
    pub y: f32,
    pub max_width: Option<f32>,
    pub max_height: Option<f32>,
}
```

These components combine in the `TextBuffer` struct, which completely specifies what text to render and how:

```rust
pub struct TextBuffer {
    pub buffer: Buffer,
    pub style: TextStyle,
    pub position: TextPosition,
    pub scale: f32,
    pub visible: bool,
    pub text_content: String,
}
```

## Renderer Architecture

The `TextRenderer` struct manages glyphon's core functionality. Since glyphon needs direct window access, the `TextRenderer` lives in the top-level `AppState` rather than being nested within the `WgpuRenderer`:

```rust
pub struct TextRenderer {
    pub font_system: FontSystem,
    pub swash_cache: SwashCache,
    pub viewport: Viewport,
    pub atlas: TextAtlas,
    pub text_renderer: GlyphonTextRenderer,
    pub text_buffers: HashMap<String, TextBuffer>,
    pub window_scale_factor: f32,
    pub window_size: winit::dpi::PhysicalSize<u32>,
    pub loaded_fonts: Vec<String>,
}
```

This architecture separates text rendering concerns from general graphics rendering while maintaining the performance benefits of GPU acceleration. The system provides a clean abstraction over glyphon's complexity while preserving its capabilities.
