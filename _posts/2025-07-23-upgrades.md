In our previous post, we covered the UI system that powers Mirador's pause menu. Now we'll look at how that same system handles the upgrade menu, which is more complex but uses the same underlying architecture.

## Using the Existing Button System

The upgrade menu builds on the same `ButtonManager` we used for the pause menu. It uses features like `ButtonSpacing::Tall` and the level text/tooltip system to display more information per button.

### Tall Button Layout

The upgrade menu uses tall buttons that span a larger portion of the window height:

```rust
ButtonSpacing::Tall(height_proportion) => {
    let width = if button.position.width > 0.0 {
        button.position.width
    } else {
        text_width + 2.0 * vertical_padding
    };
    let height = self.window_size.height as f32 * height_proportion;
    (width, height)
}
```

This gives enough space to show the upgrade name, level, and description within each button.

### Multi-Text Display

Each upgrade button shows three text elements:

```rust
let upgrade_button = Button::new("speed_upgrade", "Speed Boost")
    .with_style(upgrade_style)
    .with_level_text()
    .with_tooltip_text()
    .with_position(
        ButtonPosition::new(center_x, y(0), button_width, button_height)
            .with_anchor(ButtonAnchor::Center),
    );
```

The button manager positions the main text at the top, level text in the middle, and tooltip text at the bottom of each button.

## The Upgrade System

The upgrade menu connects to a system that manages player progression through collectible upgrades.

### Data Structure

Upgrades are defined as an enum with associated display information:

```rust
#[derive(Debug, Clone, PartialEq, Eq, Hash)]
pub enum AvailableUpgrade {
    SpeedUp,
    SlowTime,
    SilentStep,
    TallBoots,
    HeadStart,
    Dash,
    Unknown,
}

impl AvailableUpgrade {
    pub fn to_upgrade(&self) -> Upgrade {
        match self {
            AvailableUpgrade::SpeedUp => Upgrade {
                name: "Speed Up".to_string(),
                tooltip: "Increases your movement speed, making you faster and more agile.".to_string(),
                rarity: UpgradeRarity::Common,
            },
            // ... other upgrades
        }
    }
}
```

### Rarity System

Upgrades have different rarity levels that affect how often they appear:

```rust
#[derive(Debug, Clone, PartialEq)]
pub enum UpgradeRarity {
    Common,    // 40% chance
    Uncommon,  // 30% chance
    Rare,      // 20% chance
    Epic,      // 8% chance
    Legendary, // 2% chance
}
```

This creates a progression where common upgrades appear frequently while rare ones are more exciting to find.

### Upgrade Manager

The `UpgradeManager` tracks which upgrades the player has collected:

```rust
pub struct UpgradeManager {
    pub player_upgrades: HashMap<AvailableUpgrade, u32>,
}
```

It provides methods for selecting random upgrades and applying them to the player.

## When Upgrades Are Offered

The upgrade system triggers at specific points during gameplay, based on level progression.

### Level Completion

Upgrades are offered every 3 levels. When the player reaches the maze exit, the game transitions to the `ExitReached` screen where the player moves upward for 1 second, then either shows the upgrade menu or continues to the next level:

```rust
} else if state.game_state.current_screen == CurrentScreen::ExitReached {
    state.game_state.exit_reached_timer += state.game_state.delta_time;

    if state.game_state.exit_reached_timer < 1.0 {
        state.game_state.player.move_up(state.game_state.delta_time);
    } else {
        let current_level = state.game_state.game_ui.level;
        if current_level > 0 && current_level % 3 == 0 {
            state.game_state.current_screen = CurrentScreen::UpgradeMenu;
            state.upgrade_menu.show();
        } else {
            self.new_level(false);
        }
    }
}
```

### Upgrade Selection Process

When upgrades are offered, the system:

1. Shows the upgrade menu with three random upgrade options
2. Waits for player selection
3. Applies the chosen upgrade to the player
4. Continues to the next level

The weighted selection ensures that rarer upgrades appear less frequently, maintaining game balance while providing exciting moments when powerful upgrades are available.

## Upgrade Reset Mechanics

Player upgrades are reset at specific points to maintain game balance and provide fresh progression opportunities.

### Game Restart

When a player starts a new game (either through the pause menu or by completing a run), all upgrades are reset:

```rust
if game_over {
    state.game_state.player = Player::new();
    state.game_state.set_level(1);
    state.game_state.set_score(0);
    // ... other reset logic
}
```

### Title Screen Reset

When returning to the title screen, upgrades are cleared:

```rust
} else if state.game_state.current_screen == CurrentScreen::Title {
    state.upgrade_menu.upgrade_manager.player_upgrades.clear();
    state.game_state.player = crate::game::player::Player::new();
    // ... other reset logic
}
```

### New Game Reset

When starting a new game, upgrades are explicitly cleared:

```rust
} else if state.game_state.current_screen == CurrentScreen::NewGame {
    state.upgrade_menu.upgrade_manager.player_upgrades.clear();
    state.game_state.player = crate::game::player::Player::new();
    // ... other reset logic
}
```

### Reset Implementation

The reset process is straightforward:

```rust
impl UpgradeManager {
    pub fn reset_upgrades(&mut self) {
        self.player_upgrades.clear();
    }
}
```

This clears all collected upgrades, returning the player to their base abilities for the next run.

## Upgrade Menu Implementation

The upgrade menu generates buttons dynamically based on available upgrades.

### Dynamic Button Creation

The menu creates buttons based on the upgrades offered to the player:

```rust
pub fn create_upgrade_buttons(&mut self, upgrades: &[Upgrade], upgrade_manager: &UpgradeManager) {
    let window_size = self.button_manager.window_size;
    let reference_height = 1080.0;
    let scale = (window_size.height as f32 / reference_height).clamp(0.7, 2.0);

    let button_width = (window_size.width as f32 * 0.25 * scale).clamp(150.0, 400.0);
    let button_height = (window_size.height as f32 * 0.15 * scale).clamp(80.0, 200.0);
    let button_spacing = (window_size.height as f32 * 0.02 * scale).clamp(4.0, 32.0);

    for (i, upgrade) in upgrades.iter().enumerate() {
        let (level_text, tooltip_text) = upgrade_manager.get_upgrade_display_info(upgrade);

        let mut button_style = create_upgrade_button_style();
        button_style.spacing = ButtonSpacing::Tall(0.15);

        let button = Button::new(&format!("upgrade_{}", i), &upgrade.name)
            .with_style(button_style)
            .with_level_text()
            .with_tooltip_text()
            .with_position(
                ButtonPosition::new(center_x, y(i), button_width, button_height)
                    .with_anchor(ButtonAnchor::Center),
            );

        self.button_manager.add_button(button);
    }
}
```

### Text Layout

The button manager handles positioning the three text elements within each button:

```rust
if let Some(level_id) = &button.level_text_id {
    let mut level_style = style.text_style.clone();

        &level_id,

}
```

This creates a clear hierarchy with the upgrade name at the top, level information in the middle, and description at the bottom.

### Icon Display

The upgrade menu shows icons for each upgrade type:

```rust
pub fn update_icon_positions(&mut self) {
    self.icon_renderer.clear_icons();

    for button_id in &self.button_order {
        if let Some(button) = self.buttons.get(button_id) {
            if button.visible && matches!(button.style.spacing, ButtonSpacing::Tall(_)) {
                let (actual_x, actual_y) = button.position.calculate_actual_position();

                let scale = match button.state {
                    ButtonState::Hover => 1.1,
                    ButtonState::Pressed => 1.05,
                    _ => 1.0,
                };

                let icon_size = max_icon_width.min(max_icon_height);
                let icon_x = scaled_x + (scaled_width - icon_size) / 2.0;
                let icon_y = scaled_y + scaled_height * 0.5;

                let icon = Icon::new(
                    icon_x,
                    icon_y,
                    icon_size,
                    icon_size,
                    button.icon_id.clone().unwrap_or_else(|| "blank_icon".to_string()),
                );
                self.icon_renderer.add_icon(icon);
            }
        }
    }
}
```

Icons are centered in each button and scale with hover effects.

## Game Integration

The upgrade system affects player abilities through the `Player` struct.

### Upgrade Application

When an upgrade is selected, it's applied to the player:

```rust
pub fn apply_upgrade(&mut self, upgrade: &AvailableUpgrade) {
    let current_count = *self.player_upgrades.get(upgrade).unwrap_or(&0);
    self.player_upgrades.insert(upgrade.clone(), current_count + 1);

    let upgrade_info = upgrade.to_upgrade();
    println!("Applied upgrade: {} (Total: {})", upgrade_info.name, current_count + 1);
}
```

The actual game effects are implemented in the player movement and game logic systems. For example, speed upgrades modify the player's `base_speed` field, while stamina upgrades would affect `max_stamina`.

### Progression

The system tracks how many times each upgrade has been collected, allowing for level-based progression where upgrades become more effective with each collection. This encourages players to choose upgrades strategically based on their playstyle.

## Conclusion

The upgrade menu shows how the button system can handle more complex content while using the same underlying architecture. By extending the existing components with features like multi-text display and icon support, we can create richer interfaces without rebuilding the entire system.

The upgrade system provides a simple progression mechanism where players collect upgrades that modify their abilities. The rarity system ensures balanced gameplay while the level-based progression creates meaningful choices.

This approach of building complex interfaces on top of simple, tested components allows for consistent UI behavior across different parts of the game while keeping the code manageable.
